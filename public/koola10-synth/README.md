1. WHAT THIS IS
--------------------------------------------------------------------------
Koola10 Synth is a wavetable synthesizer. It plays a note, reads a stored
waveform (a "wavetable") to shape the sound, then runs that sound through a
low-pass filter and an amplitude envelope.

The sound always travels through four stages, in this order:

    MIDI note
       |
       v
   [1] WAVETABLE OSCILLATOR    <- makes the raw tone
       |
       v
   [2] LOW-PASS FILTER         <- removes brightness above the cutoff
       |
       v
   [3] AMPLITUDE ENVELOPE      <- fades the note in and out
       |
       v
   [4] OUTPUT LEVEL            <- final volume
       |
       v
   audio out (stereo, standard net VST3)

"Wavetable" means the waveform is stored as a list of numbers in a file rather
than generated by a formula. A wavetable file usually holds many waveforms
("frames") stacked one after another. The Position knob slides through those
frames, which is why one knob can make the tone travel from a smooth sine to a
buzzy square and back.

v1 is MONOPHONIC: one note at a time. Playing a new note while another is
sounding moves the single voice to the new note.

2. WHAT YOU NEED BEFORE YOU START
--------------------------------------------------------------------------
On Windows you need three things:

  a) Visual Studio 2022, with the "Desktop development with C++" workload.
     Download: https://visualstudio.microsoft.com/vs/community/
     During install, tick "Desktop development with C++". That is the only
     box you need. It includes the C++ compiler and CMake.

  b) CMake 3.22 or newer.
     Visual Studio 2022 already ships a copy of CMake, so you usually do NOT
     need to install it separately. If you do want it standalone:
     https://cmake.org/download/

  c) Git (only needed the first time, to download JUCE).
     https://git-scm.com/download/win

You do NOT need to download JUCE yourself. The build file fetches a known-good
version of JUCE automatically the first time you configure the project.

3. BUILD IT ON WINDOWS WITH VISUAL STUDIO 2022 (STEP BY STEP)
--------------------------------------------------------------------------
The project uses CMake, which means Visual Studio generates the actual build
files for you. Follow these steps exactly.

STEP 1 — Open the project folder
    Put the plugin-juce folder somewhere simple, for example:
        C:\dev\fl-studio-plugins\plugin-juce
    Avoid paths with unusual punctuation, and avoid OneDrive-synced folders.

STEP 2 — Open it in Visual Studio
    Launch Visual Studio 2022.
    On the start screen click "Open a local folder..." and choose the
    plugin-juce folder (the one containing CMakeLists.txt).
    Wait for the Solution Explorer to appear.

STEP 3 — Let CMake configure
    Visual Studio notices CMakeLists.txt and starts configuring automatically.
    The Output window says something like "CMake generation started".
    The FIRST configure downloads JUCE, so it can take a few minutes and needs
    an internet connection. Later builds are fast because JUCE is cached.

    If a yellow bar appears asking whether to trust the CMake project,
    click "Trust".

STEP 4 — Pick the build preset
    In the toolbar there is a dropdown that probably says
    "Select Startup Item" or shows a preset name. Open it and choose a
    Windows 64-bit configuration, for example:
        Koola10Synth - Windows x64 (Visual Studio Community 2022)
    If nothing appears yet, wait for configure to finish, then click
    Project > Configure Cache.

STEP 5 — Build
    Menu: Build > Build All   (keyboard: Ctrl+Shift+B)
    A clean first build takes a few minutes. When it finishes, the Output
    window ends with "Build All succeeded" or similar.

    Prefer the command line instead? Open "Developer Command Prompt for VS
    2022" and run, from inside plugin-juce:

        cmake -B build -G "Visual Studio 17 2022" -A x64
        cmake --build build --config Release

    Line 1 generates the build files. Line 2 compiles them in Release mode.
    (Release sounds better and runs faster than Debug. Use Release for real
    music making, Debug only when you want to step through code.)

4. WHERE TO FIND THE PLUGIN AFTER IT BUILDS
--------------------------------------------------------------------------
COPY_PLUGIN_AFTER_BUILD is switched on in CMakeLists.txt, so on a successful
build the finished plugin is copied to your system VST3 folder for you:

    C:\Program Files\Common Files\VST3\Koola10 Synth.vst3

If the copy was blocked (this can happen when Visual Studio is not running as
administrator) the freshly built copy is still sitting inside the build tree:

    plugin-juce\build\Koola10Synth_artefacts\Release\VST3\Koola10 Synth.vst3

You can copy that folder into the path above by hand. Right-click it, Copy,
then paste into the VST3 folder and approve the admin prompt.

A standalone player is built too, which is the easiest way to hear the synth
without opening a DAW:

    plugin-juce\build\Koola10Synth_artefacts\Release\Standalone\
        Koola10 Synth.exe

Double-click that .exe, click the Options button, and choose your audio output
device and MIDI input.

5. USING IT IN A DAW
--------------------------------------------------------------------------
FL Studio:
    Options > Manage plugins > Find more plugins > Start scan.
    Koola10 Synth appears in the plugin list as an instrument (generator).
    Drag it onto the Channel Rack, then draw notes in the piano roll and
    press play.

    If it does not appear: Options > Manage plugins > Find installed plugins,
    make sure C:\Program Files\Common Files\VST3 is in the search paths, then
    rescan.

The audio the plugin produces is standard stereo VST3 output. Nothing is
proprietary or wrapped, so it records and exports like any other VST3
instrument, and rendered audio is plain PCM that any downstream pipeline can
read as a .wav.

6. WHERE EACH DSP STAGE LIVES IN THE CODE
--------------------------------------------------------------------------
There are five source files. Here is what each one is for.

  plugin-juce/CMakeLists.txt
      The build recipe: which files to compile, that this is an instrument
      (IS_SYNTH TRUE) that accepts MIDI, that it builds a VST3 and a
      Standalone app, and that it should be copied into the VST3 folder.

  plugin-juce/Source/SynthEngine.h
      Declares the sound engine class. It lists the four stages and the
      values they need. Plain C++, no VST3 and no GUI code, so the same
      engine could be reused by an offline renderer.

  plugin-juce/Source/SynthEngine.cpp
      THE ACTUAL SOUND. Everything below happens inside SynthEngine::process().

        STAGE 1 — Wavetable oscillator
            Look for the comment block "STAGE 1 — Wavetable oscillator".
            It converts the Position knob (0..1) into a place in the table,
            reads the two nearest frames, and blends between them. The helper
            SynthEngine::sampleAt() reads a single sample and does the
            interpolation. SynthEngine::loadWavetableFile() is the part that
            reads a .wav from disk and splits it into frames.

        STAGE 2 — Low-pass filter
            Look for "STAGE 2 — Low-pass filter (juce::dsp)".
            The filter itself is declared in SynthEngine.h as
            juce::dsp::StateVariableTPTFilter<float>. Each block the code sets
            the cutoff and resonance, then processes the whole block in place.
            "In place" means the filter reads the oscillator's output and
            overwrites it — that is what puts the filter after the oscillator
            in the signal chain.

        STAGE 3 — ADSR amplitude envelope
            Look for "STAGE 3 — ADSR amplitude envelope".
            The envelope is juce::ADSR, declared in SynthEngine.h, and the
            line that matters is adsr.applyEnvelopeToBuffer(). It multiplies
            every sample by how loud the note should be at that instant.
            Note on/off events come from SynthEngine::noteOn() and noteOff().

        STAGE 4 — Output gain
            Look for "STAGE 4 — Output gain". One smoothed multiply by the
            Master Level knob.

      Smoothing: SynthEngine.h has three juce::SmoothedValue members. They
      ramp knob movements over 20 milliseconds so turning a knob while a note
      sounds never clicks. If you are new to audio code, this is the trick
      worth learning from this file.

  plugin-juce/Source/PluginProcessor.h / .cpp
      The VST3 wrapper. Talks to the DAW. It:
        - tells the host this is a stereo instrument with MIDI input,
        - defines the eight parameters (their ranges and defaults),
        - pushes the current knob positions into the engine once per block
          in pushParametersToEngine(),
        - converts incoming MIDI notes into engine.noteOn()/noteOff() calls
          inside processBlock(),
        - saves and restores the knob positions plus the loaded wavetable path.

      Want to add a parameter? Add it in createParameterLayout(), add its ID
      to ParamIDs in PluginProcessor.h, push it in pushParametersToEngine(),
      and add a row to shared/parameter_schema.json.

  plugin-juce/Source/PluginEditor.h / .cpp
      The window you see. Contains:
        - Koola10LookAndFeel: the minimalist drawing style (knob arcs,
          hairline borders, near-monochrome palette).
        - WavetableDisplay: the waveform picture at the top, redrawn 24 times
          a second so it follows the Position knob.
        - Koola10SynthAudioProcessorEditor: lays out the four labelled
          sections, the LOAD .WAV button, and keeps every knob in step with
          its parameter through SliderAttachment.

  shared/parameter_schema.json
      Machine-readable list of the parameters: ID, range, default, unit,
      which DSP stage it belongs to, and a plain-English description. Keep it
      in step with createParameterLayout().

7. THE KNOBS, ONE BY ONE
--------------------------------------------------------------------------
The window is split into four labelled sections, left to right. The label
above each knob is the knob's name; the number under it is its current value.

--- OSCILLATOR -----------------------------------------------------------

  WAVETABLE POSITION   (0 % to 100 %)
      What it does: chooses where you are inside the loaded wavetable. 0 %
      sits on the first frame, 100 % on the last, and it slides smoothly
      between every frame in between.
      What you hear: changing it re-shapes the raw tone while a note is
      playing. On a typical table, low values sound round and hollow, high
      values sound bright and buzzy. If you only load a single-frame table,
      this knob does nothing — there is only one shape to sit on.

--- FILTER ---------------------------------------------------------------

  FILTER CUTOFF   (20 Hz to 20 kHz)
      What it does: sets the frequency where the low-pass filter starts
      removing energy. Everything below it passes through untouched;
      everything above it is rolled off.
      What you hear: turn it down and the note goes dark, muffled, "under a
      blanket". Turn it up and it opens out to full brightness. Sweeping it
      slowly is the classic filter sweep.

  FILTER RESONANCE   (0 % to 100 %)
      What it does: how much the filter boosts the frequencies right around
      the cutoff point.
      What you hear: at low settings the filter sounds plain. As you raise
      it, a whistle appears at the cutoff frequency and the note takes on a
      vocal, quacking character. Pushed near the top the filter starts to
      ring on its own, almost like a second pitched note.

--- AMPLITUDE ------------------------------------------------------------

  ATTACK   (0.001 s to 5 s)
      What it does: how long the note takes to reach full volume after you
      press a key.
      What you hear: 0.001 s is instant — a click, a pluck, a percussive hit.
      A few hundred milliseconds is a swell, like a bowed string or a pad
      fading in.

  DECAY   (0.001 s to 5 s)
      What it does: how long it takes to fall from full volume down to the
      sustain level, after attack finishes.
      What you hear: short decay gives a knock or pluck that drops away
      quickly. Long decay gives a smoother, lazier slide into the held note.

  SUSTAIN   (0 % to 100 %)
      What it does: the level the note holds at while the key is still down,
      after attack and decay have finished.
      What you hear: 100 % means the note stays at full volume for as long as
      you hold it — organs and pads. Lower values mean the note settles into
      the background behind whatever else is playing. At 0 % the note dies
      away completely even though your finger is still on the key, which is
      exactly what you want for plucks and bells.

  RELEASE   (0.001 s to 10 s)
      What it does: how long the note takes to fade to silence after you let
      go of the key.
      What you hear: very short and the note stops dead. Long release and the
      sound hangs in the air after your hand has moved on — the tail that
      makes a pad feel spacious.

--- OUTPUT ---------------------------------------------------------------

  MASTER LEVEL   (-24 dB to +12 dB)
      What it does: the final volume of the plugin, applied after everything
      else, including the envelope.
      What you hear: louder or quieter, nothing else changes. Use it to match
      Koola10 Synth against the other instruments in your project. If the
      sound gets harsh when pushed up, the filter resonance is probably the
      thing to lower first.

A QUICK STARTING POINT
      Position 30 %, Cutoff 2 kHz, Resonance 0 %, Attack 0.01 s, Decay 0.3 s,
      Sustain 70 %, Release 0.4 s, Level 0 dB. That is the default patch:
      a short, clean, slightly dark tone. Load a wavetable, then slowly sweep
      Position and Cutoff while holding a note to hear what the two most
      important knobs do.

8. LOADING YOUR OWN WAVETABLE
--------------------------------------------------------------------------
Click LOAD .WAV in the top right of the plugin window and pick a .wav file.

How the file is interpreted:

  * The engine looks at how many samples the file contains and tries to split
    it into equal frames, testing frame sizes of 2048, 1024, 512, 256, 128 and
    64 samples. It takes the first size that divides the file into between 1
    and 256 whole frames.
  * If the file is a single-cycle waveform, it becomes a one-frame table and
    the Position knob has nothing to travel across.
  * If the length does not divide neatly, the whole file is treated as one
    single frame.
  * Stereo files are summed and averaged down to mono, because a wavetable is
    a shape, not a stereo image.

Practical tips:
  - Surge, Serum and Vital all export wavetables as plain .wav files; those
    work directly.
  - Files longer than about 16 million samples are truncated at that point.
  - The name of the loaded table is shown next to the button, and the path is
    saved with your project so the next session loads the same table.

9. THE PARAMETER SCHEMA
--------------------------------------------------------------------------
shared/parameter_schema.json is the machine-readable contract for the plugin's
parameters, shared with the rest of the SpiralSynth AI project. Every knob
added to the plugin must also be added there, matching the existing format.

Each entry has:
    id            the exact parameter ID string used in the C++ code
    name          the label shown to users
    group         oscillator / filter / amplitude / output
    type          float
    range         min, max, optional skew or skew_centre, optional unit
    default       the value the knob starts at
    unit          Hz, s, dB, Q, normalized, level
    automatable   whether a DAW can record movement of this knob
    dsp_stage     1 oscillator, 2 filter, 3 envelope, 4 output
    description   one sentence, plain English

The three places that must agree are: ParamIDs in PluginProcessor.h,
createParameterLayout() in PluginProcessor.cpp, and this file.

10. WHAT IS NOT IN v1
--------------------------------------------------------------------------
Being honest about the edges of this version:

  * Monophonic. One note at a time, no chord memory.
  * No anti-aliasing on the oscillator. Very high notes with bright wavetables
    can sound slightly gritty at the top of the keyboard. This is the first
    thing worth fixing in v2 (mip-mapped band-limited tables).
  * No LFO, no second oscillator, no built-in effects.
  * No preset browser inside the plugin. Your DAW saves and loads the plugin
    state, which includes all eight knobs and the wavetable path.
  * The filter is a single low-pass stage; there is no high-pass or band-pass.
  * Wavetables are mono by design.

None of these affect the rendered output format: audio always leaves the
plugin as standard stereo PCM through the VST3 audio output.

11. TROUBLESHOOTING
--------------------------------------------------------------------------
"CMake generation failed" on the first configure
    Almost always the JUCE download. Check your internet connection and that
    Git is installed and on your PATH (open a command prompt and type
    `git --version`).

The build succeeds but the plugin does not appear in my DAW
    Confirm the .vst3 folder exists in C:\Program Files\Common Files\VST3.
    If it is not there, copy it from
    build\Koola10Synth_artefacts\Release\VST3\. Then rescan plugins in your
    DAW. Make sure you are scanning VST3, not VST2.

Visual Studio says "access denied" while copying the plugin
    Copying into Program Files needs administrator rights. Either run Visual
    Studio as administrator, or copy the .vst3 folder manually.

The plugin loads but there is no sound
    - Play a note from the DAW's piano roll or a MIDI keyboard; the plugin
      does not drone on its own.
    - Check RELEASE is not so long that the previous note has not finished.
    - Check SUSTAIN is above 0 %, otherwise the note dies shortly after the
      attack.
    - Check FILTER CUTOFF is not turned all the way down.
    - Check MASTER LEVEL is not pulled right down.
    - In the Standalone app, check the audio device and MIDI input are set in
      the Options panel.

Loading a .wav does nothing
    Use a standard PCM or 32-bit float .wav. Compressed formats (MP3, M4A)
    and some exotic multi-channel files are not supported.

Everything sounds too quiet compared with my other instruments
    Use MASTER LEVEL, or turn up FILTER CUTOFF. Resonance and very dark
    settings remove a lot of energy, which is normal for a low-pass filter.
